# ADR-0009: Native prompt assembly — composite reuse, thin native layer, cache-first ordering

Status: **Proposed** (architect design, workflow step 1)
Work item: "System prompt & context assembly: composite-prompt reuse, cache-first ordering"
Full design + test plan: `architecture-notes/system-prompt-context-assembly-composite-prompt-reuse-cache-first-ordering.md` (worker artifact of the architect step).

## Context

The native session engine (`internal/orchicon`, ADR-0007) already **reuses** the composite prompt pipeline: `NativeBridge.Start` → `NewSession` takes `manifest.SystemPrompt`, which is exactly the text the opencode path delivers — `db.StablePromptPrefix` + worker identity + task/AC + project/work-item context (`contextfiles.RenderManifest`) + instructions (`buildCompositePrompt` in `internal/scheduler/workflow_reconciler.go`, `buildStandaloneComposite` in `internal/scheduler/reconciler.go`). The explicit decision of this work item is **confirmed**: no parallel monolithic native prompt. The remaining gaps, verified in-repo:

1. `loop.go:194` ships the whole composite as **one** `SystemBlock{{Text: ..., Cache: true}}` — no static/mutable split, no native layer, no memory/todo digest, no injected-context zone.
2. `buildAnthropicRequest` (`anthropic.go:202-241`) places a breakpoint on the **last** system block unconditionally (`sb.Cache || i == len(req.System)-1`) — once mutable blocks are appended after the static prefix, that rule would cache-write the mutable zone every turn (the exact anti-pattern the AC forbids: "mutable blocks NEVER appear before the breakpoint").
3. Context files are rendered from disk **at composite-build time** with no fingerprint: an unchanged file is re-read and (trivially) re-rendered every execution; a changed file silently costs a cache miss with no log/metric.
4. `bridge.recordUsage` (`bridge.go`) emits an **all-zero** `UsageRecord` — per-turn `Usage.CacheReadTokens/CacheWriteTokens` (already parsed from both wire formats: `anthropic.go` message_start/message_delta, `openaicompat.go` `prompt_tokens_details.cached_tokens`) are dropped; no session-level cache hit/miss metric exists.
5. Anthropic supports `cache_control: {"type":"ephemeral","ttl":"1h"}`; the repo hardcodes `ephemeral` 5m (the `anthCacheCtrl` struct has no TTL field).

## Decision

**D1 — Assembly stays in `internal/orchicon`; composite is consumed verbatim.** New file `internal/orchicon/prompt.go` (package `orchicon`) owns the native-side layout. The scheduler composite is the **static prefix**, byte-for-byte; nothing in the native layer re-renders project goals, context files, worker profile, or task/AC. `Identity.SystemPrompt` (already the composite) is the prefix source. This keeps opencode-driven and native workers prompt-identical — consistency is the feature.

**D2 — Wire shape: `TurnRequest.System` becomes a two-zone block list.**
`AssembleSystem(sess *Session) []SystemBlock` (new, prompt.go) returns, in order:
- `[0]` `{Text: composite (identity.SystemPrompt) + NativeStaticLayer, Cache: true}` — the **static prefix + cache breakpoint**. The thin native static layer is a constant (`const NativeStaticLayer`) appended to the composite inside the SAME cached block, covering **exactly** four topics and nothing more: (a) identity authority (you are an Orchicon worker running a native in-process session; purpose + task come from the composite; work the task, use your tools, report via the summary contract); (b) tool discipline (batch independent operations into one call; never re-read content already in context; prefer one turn with several calls over N turns); (c) todo/memory usage (maintain the todo list every turn via `todowrite`; persist durable facts to memory notes, keep transient state in-session); (d) environment facts that are static per run-class (OS linux, runtime container, project dir, git branch/worktree path from the manifest — these are constant within a run and identical inputs → identical bytes, so they do not break byte-identity). No safety block, no loop mechanics — the composite already carries them.
- `[1]` `{Text: mutableDigest, Cache: false}` (omitted when empty) — the **mutable zone**: session memory digest + current todo state + any queued injected context, rendered by `renderMutableZone` from live session state. It NEVER precedes block 0's breakpoint.
- History remains append-only in `req.Messages` (unchanged).
`loop.go` builds `req.System = AssembleSystem(s)` once per turn. Mutable-zone content changes (a new todo write) alter only block 1 → the cached prefix is untouched → hit every turn.

**D3 — Anthropic breakpoint rule fix.** In `buildAnthropicRequest`: when **any** system block carries `Cache: true`, breakpoints are placed **only** on explicitly-flagged blocks; the current "last block always" behavior remains the fallback when no block is flagged (backward-compatible with existing fixtures/tests). Default policy `system+tools` keeps the last-**tool** breakpoint. Add `TTL string` to `anthCacheCtrl` (omitempty) emitted as `{"type":"ephemeral","ttl":"1h"}`; selected via `CacheControlTTL` extension: new values `"5m"` (default) / `"1h"`, resolved from env `ORCHICON_ANTHROPIC_CACHE_TTL` at client construction (field `AnthropicClient.CacheTTL`). `DECISION (revisitable)`: 1h TTL default stays OFF — it multiplies cache-write cost 2× (Anthropic prices 1h writes at 2.0× base vs 1.25×) and only pays off for inter-execution gaps >5min; revisit via tenant settings in the usage/observability task.

**D4 — OpenAI-compat needs no code for caching** — implicit prefix caching requires only byte-stable ordering, guaranteed by D2 (block 0 first, joined by the existing `systemText` with a fixed `\n\n` separator; mutable zone last). `q.MergeSystemIntoUser` path keeps the same order (system text prepended to the FIRST user message before history).

**D5 — Context-file hash check + verbatim reuse (the cross-execution cache lever).** New file `internal/contextfiles/fingerprint.go`: `Fingerprint(paths []string, projectDir string) (digest string, perPath map[string]string) (…)` → actually `Fingerprint(paths []string, projectDir string) (string, error)` returning a SHA-256 over the ordered list of `resolved_path + "," + size + "," + mtime.UnixNano() + "," + sha256(content)` per file (directories: the walk listing + per-file entries, in `WalkDir` order). A cache package-level store in `internal/scheduler` (`promptCache`) keyed on `tenantID+"/"+projectID+"/"+fingerprint` → the previously rendered composite prefix **plus its bytes**. On dispatch, `buildCompositePrompt` / `buildStandaloneComposite` call `contextfiles.Fingerprint`; on hit they reuse the stored rendered section **verbatim** (no re-read, byte-identical → prefix cache survives across executions) and log `INFO orchicon prompt-prefix cache hit fingerprint=<short>`; on miss they re-render, store, and **log the per-path diffs** (which file's hash changed) at `INFO` — "any prefix change is logged (it costs a cache miss)". The rendered section is written to `ExecutionManifest.PromptFingerprint string` (new field) and into the session's `TransSession` header so usage records can attribute cache behavior. Store is in-process (bounded LRU, 64 entries) — cross-**process** persistence is explicitly a non-goal (a control-plane restart just pays one miss).
- `DECISION (revisitable)`: fingerprinting lives in the **scheduler** (composite build), not the native session, because the composite is built once per execution there and both adapters (opencode + native) benefit identically; the native layer stays a pure consumer.

**D6 — Cache metrics per session.** `Session` gains `cacheStats` (mutex-guarded): per-turn accumulation of `Usage.CacheReadTokens` / `CacheWriteTokens` (already normalized by both wire clients) and turn-level hit/miss classification — **hit** = `CacheReadTokens > 0` for the turn, **miss-write** = `CacheWriteTokens > 0`, else `none` (providers without cache reporting). On terminal, `bridge.recordUsage` fills the real totals into `UsageRecord.PromptTokens/CacheReadTokens/CacheWriteTokens` (replacing the placeholder zeros) — the usage-record path (migrations `20260828` cache columns) already stores them. Additionally emit OTel counters via `telemetry.Meter()` (same pattern as `aigateway/service.go:459`): `orchicon_prompt_cache_turns{result=hit|miss_write|none}` (Int64Counter) and `orchicon_prompt_cache_tokens{class=read|write}` (Int64Counter); no-op when OTel is unset, never control-flow. Session terminal also logs `INFO orchicon session cache summary turns_hit=N turns_miss=M read_tokens=X write_tokens=Y prefix_fingerprint=Z`.

**D7 — Todo/memory digest wiring (thin).** The mutable zone consumes only state the session already has: latest todo list (the `todowrite` tool-call args already flow through `executeTools`; `Session` records the latest payload — reuse `internal/execution/todos.go`'s tolerant parser shape, `{"todos":[{content,status,priority}]}`, rendered as a 1-line-per-item digest) and a **session memory notes** list: a small in-session store on `Session` (`noteMu`, `notes []string`) appended by a new native tool `orchicon_memory_note` registered in the native tool surface (the tool-suite's registry; if the tool is absent, the digest simply renders todos only). Injected mid-run human messages already live in history (append-only) — they are NOT re-rendered into the mutable zone (avoids duplication); the zone's "injected messages" slot is reserved for context injected *between* sessions (resume notes), currently empty.

**D8 — Resume/continuation interaction.** `AssembleSystem` is deterministic given (composite, native layer, memory notes, todos): on resume, replay rebuilds todos/notes from the transcript (tool_call events for `todowrite` / `orchicon_memory_note`), so the static prefix is unchanged and the provider cache benefits immediately within the 5-min TTL.

## Test plan (implementation step inherits this)

- **Byte-identity** (`prompt_test.go`): two `AssembleSystem` calls with identical inputs → identical block-0 bytes; two full executions (fake provider capturing requests) with identical inputs → identical static prefix bytes end-to-end.
- **Order test**: assemble with non-empty mutable zone → assert no block with mutable content appears before the breakpoint block; assert mutable zone `Cache:false`.
- **Breakpoint placement fixtures per wire format**: anthropic capture-server test — flagged block carries `cache_control`, trailing mutable block does NOT (this also pins the D3 rule change); with no explicit flags, last-block fallback preserved; TTL field serialized when set. openaicompat — no `cache_control` emitted; system text = static+"\n\n"+mutable in that byte order; merge-into-user ordering preserved. ollama/legacycc — `systemText` unchanged (concatenation already order-stable).
- **Fingerprint tests** (`contextfiles`): unchanged tree → same digest; touch/modify/edit each of {file content, file size, dir listing, path order} → digest changes; store hit → rendered section byte-equal to first render; miss → log line emitted (capture via slog handler).
- **Metrics tests**: fake provider emitting usage events → terminal `UsageRecord` carries summed cache tokens; counter emission no-panic when telemetry unset.
- **Native-layer cap test**: `NativeStaticLayer` byte length bounded (<2 KiB) and contains the four topic headings — guards against prompt creep (the AC's "and nothing more").

## Consequences

- Native and opencode workers share one composite prompt source; the native delta is a constant <2 KiB string, trivially auditable.
- Anthropic: static prefix cached across turns (per-session) AND across executions within TTL (D5's verbatim reuse keeps prefix bytes stable so execution N+1 hits execution N's cache when inputs are unchanged); 1h TTL available behind env flag for slow workflow cadences.
- OpenAI-compat: implicit caching works because ordering is byte-stable; zero wire changes.
- One behavior change in a shared helper (`buildAnthropicRequest`): flagged-blocks-only when any flag present — existing tests pass (they flag explicitly or flag nothing); new fixtures pin both modes.
- Mutable-zone churn (todo updates) no longer invalidates the cached prefix; cost model improves with turn count (long native runs benefit most).
- Usage records gain real cache attribution for native executions; operator visibility via OTel counters + terminal log line.
- In-process prompt cache bounded (LRU 64) and dies with the control plane — a restart costs exactly one re-render per active project, not a correctness issue.
- No DB migration: `PromptFingerprint` rides existing manifest/transcript JSON surfaces and `usage_records` cache columns (`20260828`).
