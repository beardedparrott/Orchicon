# ADR-0008: MCP client — stdio + streamable HTTP & config resolution

Status: **Proposed** (architect design, workflow step 1)
Work item: "MCP client: stdio + streamable HTTP & config resolution"
Full design + test plan: `architecture-notes/mcp-client-stdio-streamable-http-config-resolution.md` (worker artifact of the architect step).

## Context

The native adapter (`internal/orchicon`, ADR-0003/0007) runs the agent loop in-process and executes tools through the `orchicon.ToolRegistry` contract (`Defs() []ToolDef` + `Execute(ctx, name, argsJSON)`, `ToolDef{Name, Description, ParamsJSON}`). Today the only MCP surface in the repo is the **server** sidecar (`internal/mcp/`): stdio servers that expose Orchicon's own tools to opencode workers. There is **no MCP client** — native-adapter workers cannot consume external MCP tools. This work item adds it, built on the official Go SDK `github.com/modelcontextprotocol/go-sdk` (v1.7.x, co-maintained with Google) — hand-rolled JSON-RPC is explicitly out of scope.

Requirements (work item): both stdio (`CommandTransport` — server runs as a subprocess of the control plane) and streamable HTTP (`StreamableClientTransport` — remote servers with header auth); connections established **lazily per session** (never at control-plane boot) but **tool discovery at session start** so signatures are present in the model's first request; discovered tools merged into the native tool registry as `mcp__<server>__<tool>` with JSON schemas passed through; call routing via the client with per-call timeouts + cancellation; stdio children cannot outlive a dead control plane (Linux PDEATHSIG or equivalent + a boot-time sweep of stale children); config resolution **worker selection → project selection → none** over the tenant-configured MCP server list (storage owned by the adapter-settings task — this task consumes it, does not define storage); a selected-but-missing/unreachable server fails the session actionably (or degrades per config), never silently. Resources/prompts are a non-goal for v1; OAuth deferred (header/bearer auth in v1).

Design constraints verified in-repo:
- `internal/orchicon/session.go:44-50` — `ToolRegistry` interface; production never sets `SessionConfig.Tools` today (only test mocks do, e.g. `qa_harness_test.go` `mockTools`), so the MCP-backed registry is a pure addition wired at session construction in `bridge.go`.
- `internal/orchicon/loop.go:191` — `req.Tools = s.tools.Defs()` feeds provider tool schemas; providers consume `ToolDef.ParamsJSON` verbatim (anthropic.go:233, openaicompat.go:120-127), so passing the raw MCP `inputSchema` through as `ParamsJSON` surfaces proper signatures to the model with zero provider changes.
- Worker selection surface **exists today**: `worker_versions.permissions` jsonb carries `mcp_servers: [{id, command}]` (frontend `WorkerFormSections.tsx` Permissions section → `MCPPicker`/`MCPConfig{id, command}`). The tenant server list shape already exists as `mcpEntry{Type, URL, Command (string|[]string), Enabled}` in `internal/aigateway/mcp.go` (discovered via `opencode debug config`) — the natural contract for the consumed server list. Project selection has **no storage yet** — contract-only, defined by the adapter-settings task.
- go-sdk v1.7.0 (verified buildable with Go 1.26.4; deps: yosida95/uritemplate, segmentio/encoding, golang-jwt, google/jsonschema-go, x/oauth2, x/time, x/tools): `mcp.NewClient(&mcp.Implementation{Name, Version}, opts)` → `Client.Connect(ctx, transport, nil)` → `*ClientSession`; `cs.ListTools(ctx, nil)`, `cs.CallTool(ctx, ...)`, `cs.Close()`. **Stdio transport is the struct `mcp.CommandTransport{Command: *exec.Cmd, TerminateDuration}`** (no constructor) — set `cmd.SysProcAttr = &syscall.SysProcAttr{Pdeathsig: SIGKILL, Setpgid: true}` directly on the `exec.Cmd` before Connect; teardown on Close: close stdin → wait 5s → SIGTERM → SIGKILL (verified in cmd.go). **HTTP transport is the struct `mcp.StreamableClientTransport{Endpoint, HTTPClient, MaxRetries, DisableStandaloneSSE, OAuthHandler}`** (no constructor; header auth via a custom `HTTPClient` whose RoundTripper injects headers; `OAuthHandler` exists for the deferred OAuth work). Server-side fixture API for tests: `mcp.NewServer` + `mcp.AddTool(server, &mcp.Tool{Name, Description, InputSchema any}, handler)` + `mcp.NewStreamableHTTPHandler(func(*http.Request) *mcp.Server, opts)` (HTTP) / `server.Connect(ctx, &mcp.StdioTransport{})` (stdio).
- No PDEATHSIG exists in the repo today (`cmd/orchicon/procattr_unix.go` sets `Setpgid` only). Reusable lifecycle hooks: `internal/server/server.go` boot + 30s adopt sweep (~694-760) and `scheduler.ExecutionReaper` — the MCP stale-child sweep hooks the boot sweep.
- `architecture-notes/` is gitignored (`.gitignore:63`) — the ADR is the committed artifact; the notes file is the run's worker artifact per ADR-0007 convention.

## Decision

1. **Package**: new `internal/mcpclient/` wrapping go-sdk v1.7.0. The SDK is the only protocol implementation; our code owns config resolution, lifecycle, registry merging, and error surfacing — never JSON-RPC. `go.mod` gains `github.com/modelcontextprotocol/go-sdk v1.7.0`.
2. **Transports**: stdio via the go-sdk struct `mcp.CommandTransport{Command: cmd}` where `cmd = exec.Command(argv[0], argv[1:]...)` carries Linux `SysProcAttr{Pdeathsig: SIGKILL, Setpgid: true}` (Setpgid for group kill on Close); HTTP via the go-sdk struct `mcp.StreamableClientTransport{Endpoint: url, HTTPClient: client, MaxRetries: 2, DisableStandaloneSSE: true}` where `client` is an `http.Client` whose RoundTripper injects the config `headers` map (e.g. `Authorization: Bearer …`), TLS trust from system pool, clean close.
3. **Per-session manager** `mcpclient.Manager` implementing `orchicon.ToolRegistry`: constructed lazily at session start (never at boot) from the resolved config; `Defs()` returns merged native tools `mcp__<server>__<tool>` with the server's raw `inputSchema` passed through as `ParamsJSON`; `Execute(ctx, name, argsJSON)` routes `mcp__<server>__<tool>` → `cs.CallTool` with a per-call timeout (default 120s, server-config-tunable) and cancellation via the caller's ctx; errors map actionably (`mcp: server "<id>" unreachable: …`, `mcp: tool "<name>" failed: …`, `mcp: tool "<name>" timed out after 120s`). `Close()` kills stdio children (happy path) and closes HTTP sessions; called at session end by the bridge.
4. **Config resolution** via a consumed contract interface `ConfigSource` (adapter-settings task owns storage): `ServerList(ctx) ([]ServerSpec, error)`, `WorkerSelection(ctx, workerID) ([]ServerID, error)`, `ProjectSelection(ctx, projectID) ([]ServerID, error)` where `ServerSpec{ID, Type: stdio|http, Command []string, URL, Headers map[string]string, Timeout time.Duration}`. Resolution order: worker selection → project selection → none. No worker selection → inherit project defaults; no project selection → no MCP tools. Selected-but-unconfigured or unreachable server → session start fails actionably with the offending server ID (or degrades per a per-server `OnError: fail|degrade` config flag, default `fail`) — never silent.
5. **Lifecycle**: stdio children are owned by the session and killed at session end (explicit Close + group kill). PDEATHSIG (SIGKILL on parent death, Linux) guarantees a child cannot outlive a dead control plane even on kill -9. A **boot-time stale-child sweep** in `internal/server/server.go` boot path (hooked alongside the existing adopt sweep ~694-760) reaps MCP children whose controlling execution no longer exists in the scheduler's live set — covers the non-Linux/container edge and pre-existing orphans after a crash. Remote (HTTP) connections close cleanly.
6. **Wiring**: `internal/orchicon/bridge.go` resolves config per execution via `ConfigSource`; when non-empty, constructs the `Manager` and sets `SessionConfig.Tools = manager`. Discovery runs at session start (`Manager.Start` → connect + `ListTools` for each selected server) so the model's first request carries full signatures. A manager whose server fails discovery returns an actionable session-start error.
7. **Tests**: in-repo test MCP server (go-sdk fixture `internal/mcpclient/testserver/` — `mcp.NewServer` + `AddTool` handlers: echo, error-forcing, sleep-with-cancel) served over BOTH transports (stdio `StdioTransport`, HTTP `httptest`/`NewStreamableHTTPHandler`). No external network in default tests. Coverage: discovery merge + naming + schema pass-through; call; tool error; per-call timeout; cancellation (ctx cancel mid-call); lifecycle kill at session end; orphan prevention (spawn the control-plane-shaped parent, connect a stdio child, kill -9 the parent, assert no surviving child — PDEATHSIG verification); resolution order (worker→project→none, inherit, missing server fails actionably).
8. **Non-goals (v1)**: MCP resources/prompts (recorded as future work); OAuth dance (header auth only); SSE transport (out of scope; stdio + streamable HTTP only per work item).

## Consequences

- Native-adapter workers gain external MCP tools with proper JSON schemas in the model's first request; no provider-layer changes (schemas flow through `ParamsJSON`).
- Zero cold-cost change: no connections at control-plane boot; per-session connect + discovery only when the resolved config selects servers.
- Stdio children cannot outlive a dead control plane (PDEATHSIG + boot sweep double coverage); session-end Close is the clean-path kill.
- Tool namespace `mcp__<server>__<tool>` is unambiguous across multiple servers; collisions with native tool names are impossible by construction (reserved prefix).
- A hard contract dependency on the adapter-settings task: this task ships `ConfigSource` (interface + consumption + tests) and the tenant server-list/selection storage must implement it before/with the feature. Until storage lands, `ConfigSource` is satisfied by a no-op/default implementation — resolution yields no MCP tools (safe degradation, matches "project with none gets no MCP tools").
- Fail-actionable semantics: a misconfigured selection is a loud, session-start error naming the server, never a silent hang or missing tool.
- Cost: go-sdk + transitive deps added to the module (small, pure-Go); per-session connect/discovery latency is additive to session start, bounded by per-server timeouts.

## Alternatives considered

- **Hand-rolled JSON-RPC client** — rejected: work item mandates the official SDK (co-maintained with Google); hand-rolling protocol handling would re-derive spec drift, auth, and lifecycle bugs the SDK already owns.
- **Reuse opencode's MCP config assembly (`internal/opencode/config.go` `mcp` merge)** — rejected: that path only builds a config file for the opencode serve subprocess; the native adapter needs an in-process client session API. The `mcpEntry` shape is reused as the server-list contract shape, not its transport.
- **Connect eagerly at control-plane boot** — rejected: violates the lazy-startup requirement and bloats cold cost; per-session connect keeps cold cost near zero and isolates server failures to the session that selected them.
- **Do tool discovery lazily on first tool call** — rejected: the model's first request must already carry discovered signatures (work item AC); discovery at session start is the decided point.
- **Sweep-only orphan prevention (no PDEATHSIG)** — rejected: a sweep is asynchronous and cannot cover a killed parent in all crash orders; PDEATHSIG is the synchronous guarantee on Linux, the sweep is the belt-and-suspenders reaper.
- **Store the server list / selections in this task** — rejected: explicitly owned by the adapter-settings task; this task defines and consumes the `ConfigSource` contract only.
