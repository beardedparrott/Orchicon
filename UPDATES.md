| 123 | Feature | Session transport | Stream + persist reasoning for Ask Orchicon: reasoning parts are unwrapped from the SSE bus in the live turn loop via the same `LegacyEventFromBus` mapping executions use, accumulated separately from the reply text (never folded into content), and persisted per turn on the assistant message (`ask_orchicon_messages.reasoning jsonb NOT NULL DEFAULT '[]'`, forward-only migration) — partial reasoning survives error/stop/timeout turns. `ChatMessage` gains `repeated string reasoning = 10` (delivered via the existing `ListMessages` poll, the F4 reasoning-bubble data path) and the `ChatStreamResponse` oneof gains a typed `ReasoningChunk` event (field 7, defined-but-not-emitted like `text_chunk`, for a future SSE surface). | 122 | Bug fix | Workflow engine | Un-wedge the loop_decision DAG and make force-progress skip only stuck steps. Root cause of a prod stall: a SUPERSEDED loop-decision iteration created in the SAME transaction as the active one shares `created_at`, and `runByID` ("last row wins" over `ORDER BY created_at`) could shadow the active pending run with the superseded succeeded one — the loop decision never dispatched, downstream never fired, and the run sat "running" until force-progress (which then skipped real work). Fixes: `ListWorkflowStepRuns` orders by `created_at, id` and `runByID` prefers non-superseded rows; the upstream-failed branch no longer spawns a duplicate iteration while one is already pending; and `ForceProgressWorkflowRun` now forces only in-flight steps and pending steps whose DAG deps are satisfied, leaving steps with unsatisfied deps PENDING so the reconciler dispatches them (it never skips a PR-merge step again). |
| 121 | Feature | Session transport | Ask Orchicon turn lifecycle matches executions' resilient pattern: `ChatStream` is now a send-and-ack RPC — the reply is collected on a request-independent detached context (survives tab close / disconnect) and delivered by polling `ListMessages` within the new `ORCHICON_ASK_REPLY_WINDOW` (default 30m); **Stop** is a first-class `AbortConversationTurn` RPC that aborts the serve session turn (session kept for the next message) and cancels the in-process turn registry; serve loss mid-reply re-attaches to the same session (watchdog preserves the data dir) or falls back to a fresh session seeded from the DB transcript; a serve down at send time fails fast after `ORCHICON_ASK_SERVE_DOWN_GRACE` (default 15s) instead of looping to the reply window; failed/timeout/stopped turns are persisted as error messages (`MessageMetadata.error`) with a Retry affordance that re-sends the most recent user message; one turn per conversation (FailedPrecondition while pending). QA round: the DB-backed turn tests now run against real Postgres (tenant injection in the abort handler test + real `buildSystemPrompt` content assertions instead of literals), and the conversations sidebar refreshes when a reply lands. |
