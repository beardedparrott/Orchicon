| 194 | Feature | Dependency graph | Cycle detection + validation enforced on the work-item dependency DAG. The DAG invariant now lives at the persistence boundary: new forward-only migration `db/migrations/20260821000000_enforce_work_dag_acyclic.sql` adds the codebase's first trigger (`enforce_work_dag_acyclic`, `BEFORE INSERT OR UPDATE` on `work_item_dependencies`) — it rejects a self-loop (`from_id = to_id`) for every edge type (including `relates_to`), exempts `relates_to` from the reachability walk (a symmetric, non-ordering relationship), and uses a `WITH RECURSIVE` reachability check over `depends_on`/`blocks` edges to reject any direct or multi-hop cycle (`RAISE EXCEPTION` aborts the transaction, so invalid graphs never persist — covering the API RPCs, any future bulk-import path, and raw SQL). New DB-backed tests cover direct/multi-hop cycles (add + set-replace), `blocks` cycles, symmetric + mixed-case `relates_to` exemption, the create-path invariant, a trigger backstop test that raw-SQL cyclic/self-loop inserts are rejected and never persist while valid bulk inserts (incl. `relates_to`) succeed, and a deterministic concurrent-insert regression test (two transactions inserting `A→B`/`B→A`, barrier-verified on the advisory lock) proving the race is closed. `make migrate-hash` rehashed.
